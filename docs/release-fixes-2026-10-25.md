# Claude Export 1.3.1 发版问题修复

日期：2026-10-25。本次修复对应检查记录中的 4 项 P1 和 2 项 P2，保留了工作区此前的导出优化及既有测试。

## 修复结果与原因

| 问题 | 原因 | 修复后的行为 |
| --- | --- | --- |
| 发布版本重复 | 本地仍为商店已发布的 1.3.0 | manifest、package、lockfile 和 ZIP 统一为 1.3.1 |
| 不同回答分支混入导出 | 直接线性解析整个 `chat_messages` | 根据 `current_leaf_message_uuid` 回溯父链并恢复顺序；只有单一叶节点时才允许推断分支。缺失节点、循环、重复 ID 或歧义会停止导出；树形接口缺少分支信息时也不再直接放行 |
| 多组织导出失败 | 查错组织后重复请求同一组织 | 优先使用会话组织信息或当前页面的 `lastActiveOrg`，再看明确的活跃标记。仅在 403/404 时查找其他组织，每次最多尝试 5 个；401、429、服务故障不会触发跨组织遍历，取消会停止后续请求 |
| 并发任务覆盖控制器 | 各入口分别创建控制器，检查范围不同 | 单次、批量、Notion 和 Obsidian 通过同一函数同步占用任务位置；同步预检前即占用，批量预检与正式导出复用同一控制器。预检失败后按任务身份释放；已交给后台的 Notion 任务仍参与忙碌判断 |
| 合法单角色会话被拦截 | 把缺少 user/assistant 角色一概视为内容丢失 | 已通过分支检查且没有丢失解析消息的 Claude 响应，可导出单角色会话；若原始消息未成功解析，仍阻止导出，避免放宽检查后掩盖真实缺失 |
| 选文件耗时导致保存误报失败 | 通信超时涵盖了原生文件选择时间 | 后台先持久化请求 ID 并立即确认接收，再启动下载。前台分别等待文件选择及下载完成；确认消息丢失时按请求 ID 查询，不重复启动下载。请求状态绑定来源标签页和文档，下载终态或安全上限到达时释放 Blob URL |

保存协议保留了旧版内容脚本的请求处理，便于扩展更新后仍打开的页面继续使用原路径。新协议不增加权限。文件选择保留 30 分钟安全上限；获得 downloadId 后沿用 5 分钟下载完成等待，等待超时后仍保留 Blob，直到收到终态或达到 30 分钟资源清理上限。
